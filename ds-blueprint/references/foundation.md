# Foundation Pass — Methodology (Phase 2)

Consumer: ds-blueprint Phase 2. Loaded on `--init`, or when the profile lacks foundation lines.

## Evidence sweep

What the project *is* and *claims*: README/docs promises, code capabilities, git history, existing profile lines, prior user statements. Every proposed value cites its evidence.

## Idealized draft

`Mission` (one line, who-gets-what-outcome), `Target`, ranked `Priorities`, constraints split honestly into `Constraints` (soft) vs `Red lines` (hard NOs). Where the evidence supports a sharper mission or a stronger target than stated, draft the sharper version — from evidence, never invention.

## Decision interrogation

For every normative line:
- (a) current value + evidence
- (b) does the evidence still support it, does it earn its keep (a constraint with no protective value → removal proposal stating what it costs and what removing it frees)
- (c) a better alternative with concrete rationale when one exists

## Resolution

Default (`derived` mode): write the best-evidenced value for every line, mark the profile write `foundation: derived-from-evidence` in the summary, and list every line whose evidence was thin as `only you can do: confirm {line}` — a thin-evidence line is written with the most conservative reading (private, free/internal, keep framework) and never invented. `--ask`: present one per-line table `current → proposed | evidence | rationale`, ask per line accept / edit / keep-current, iterate until every line is confirmed.

## Decision durability (W13)

A user-confirmed line is settled: it never silently flips, and it is re-raised only with named cause (new project evidence, or a materially better derivation on `--init --ask`). Re-litigating an unchanged conclusion is forbidden.
