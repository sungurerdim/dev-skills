# Accessibility — WCAG 2.2 AA as engineering checks

Loaded for graphical UIs; a terminal-only product uses [cli.md](cli.md). Target: WCAG 2.2 level A and AA; a rule built on an AAA criterion says so and never blocks an AA claim. Static greps find candidates; when the app can be served, an engine run (axe-core, pa11y, Lighthouse) adds rendered evidence, and a keyboard plus screen-reader pass (VoiceOver, NVDA, TalkBack) stays required — automated tools find only part of the failures.

### AXE-01 [CRITICAL] Not operable by keyboard
- **Detect:** click handlers on non-interactive elements (`<div onClick>`, `<span @click>`) without `role`, `tabindex="0"` and Enter/Space handling; positive `tabindex` reordering focus; focus that cannot leave a widget (keyboard trap); custom controls with no keyboard path (Flutter `GestureDetector` without `FocusableActionDetector`, Compose `clickable` on a non-focusable node, SwiftUI `onTapGesture` on a plain view).
- **Mech:** T `git grep -nIE '<(div|span|li|td|img)[^>]*(onClick|@click|on:click|v-on:click|\(click\))=' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'` · `git grep -nIE 'tabindex=["{]?[1-9]' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'`
- **Fix:** native `<button>`, `<a href>` and form controls (or the platform's button widget); where a custom control is unavoidable, add the role, focusability and key handlers; remove positive tabindex and fix DOM order instead.
- **Impact:** keyboard, switch and screen-reader users cannot reach or use the control at all.
- **Source:** WCAG 2.2 SC 2.1.1 Keyboard, 2.1.2 No Keyboard Trap, 2.4.3 Focus Order.

### AXE-02 [CRITICAL] Focus not visible
- **Detect:** `outline: none` or `outline: 0` with no `:focus-visible` replacement; a focus style under 3:1 against its surroundings; framework themes that remove the focus highlight.
- **Mech:** T `git grep -nIE 'outline:[[:space:]]*(none|0)([[:space:]]|;|$)' -- '*.html' '*.css' '*.scss' '*.less' '*.vue' '*.svelte' '*.tsx' '*.jsx'`
- **Fix:** a `:focus-visible` style, e.g. `outline: 2px solid currentColor; outline-offset: 2px`, on every interactive element; keep the platform focus highlight on native apps.
- **Impact:** keyboard users cannot see where they are, so every action is a guess.
- **Source:** WCAG 2.2 SC 2.4.7 Focus Visible (AA); SC 2.4.13 Focus Appearance (AAA) for the size and contrast bar.

### AXE-03 [CRITICAL] Text contrast below 4.5:1
- **Detect:** text and background pairs below 4.5:1 (3:1 for text ≥ 24 px, or ≥ 18.66 px bold), checked in every theme (light, dark, high contrast); placeholder and disabled-looking text that carries information; text over images without a scrim.
- **Mech:** M (compute ratios from the colour tokens of each theme; an engine run's `color-contrast` result when the app can be served)
- **Fix:** adjust the token, not the instance; add a scrim behind text on images.
- **Impact:** low-vision users and anyone in sunlight cannot read the content.
- **Source:** WCAG 2.2 SC 1.4.3 Contrast (Minimum).

### AXE-04 [CRITICAL] Control without a correct accessible name
- **Detect:** icon-only buttons and links without `aria-label` or visible text (Flutter `IconButton` without `tooltip`, Compose `Icon` with `contentDescription = null` on an action, SwiftUI image buttons without `accessibilityLabel`); `aria-label` and `aria-labelledby` on one element (one is discarded); an accessible name that does not contain the visible label; generic link text ("click here", "read more") with no context; `title` as the only name.
- **Mech:** T `git grep -nIE '<(button|a)[^>]*>[[:space:]]*<(svg|img|i|span class="icon)' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'` · `git grep -nIE 'aria-label=[^>]*aria-labelledby=|aria-labelledby=[^>]*aria-label=' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'`
- **Fix:** one naming mechanism per control, starting with the visible label; icon-only actions get a label that names the outcome; verify in the browser or platform accessibility tree.
- **Impact:** screen readers announce "button" with no purpose, and voice-control users cannot say the visible label to activate it.
- **Source:** WCAG 2.2 SC 4.1.2 Name, Role, Value; SC 2.5.3 Label in Name; SC 2.4.4 Link Purpose; W3C APG, Names and Descriptions.

### AXE-05 [HIGH] Custom widget without its APG pattern
- **Detect:** tabs, menus, listboxes, comboboxes, grids, trees, accordions and dialogs built from generic elements without the pattern's roles and states (`aria-selected`, `aria-expanded`, `aria-controls`, `aria-modal`), or with roles but without its keyboard model: arrow keys inside the widget, one Tab stop for the whole composite (roving tabindex or `aria-activedescendant`), Home/End/Escape where the pattern names them.
- **Mech:** T `git grep -nIE 'role="(tablist|tab|menu|menubar|menuitem|listbox|combobox|grid|tree|treeitem|dialog)"' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'`
- **Fix:** use the native element or a vetted headless library; otherwise implement the matching APG pattern's role, state and keyboard table.
- **Impact:** ARIA without its behaviour promises interactions keyboard and screen-reader users then cannot perform.
- **Source:** W3C ARIA Authoring Practices Guide (https://www.w3.org/WAI/ARIA/apg/); WCAG 2.2 SC 4.1.2.

### AXE-06 [HIGH] Image without a text alternative
- **Detect:** `<img>` without `alt`; informative images with filler alt ("image", file names); decorative images with non-empty alt; charts without a text summary or data table; text baked into images; native images without `semanticLabel`/`contentDescription`/`accessibilityLabel` or not excluded when decorative.
- **Mech:** T `git grep -nIE '<img[[:space:]]' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte' '*.astro' | grep -v 'alt='`
- **Fix:** describe purpose for informative images, `alt=""` (or exclude from semantics) for decorative ones, a long description for complex graphics, real text instead of images of text.
- **Impact:** blind users miss the information or hear file names and noise.
- **Source:** WCAG 2.2 SC 1.1.1 Non-text Content, SC 1.4.5 Images of Text; W3C WAI, alt decision tree.

### AXE-07 [HIGH] Form field without a persistent label
- **Detect:** inputs, selects and textareas with no `<label for>`, wrapping label or `aria-labelledby`; placeholder used as the only label; required or format constraints shown only by colour or only after an error; native text fields without a label parameter.
- **Mech:** T `git grep -nIE '<(input|select|textarea)[[:space:]]' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte' | grep -v -e 'type="hidden"' -e 'aria-label' -e 'type="submit"' -e '<label'`
- **Fix:** a visible label tied to every field; instructions and required markers in text before the field.
- **Impact:** screen-reader users hear unlabeled edits, and everyone loses the hint once they start typing.
- **Source:** WCAG 2.2 SC 1.3.1 Info and Relationships, SC 3.3.2 Labels or Instructions.

### AXE-08 [HIGH] Headings and labels do not describe the structure
- **Detect:** skipped heading levels, several `<h1>` per view, styled text used as a heading without heading semantics (Flutter `Semantics(header: true)`, iOS `.isHeader` trait), headings used only for size; headings and labels that do not describe their section or field.
- **Mech:** T `git grep -oIE '<h1[[:space:]>]' -- '*.html' | sort | uniq -c | awk '$1 > 1'`
- **Fix:** one top heading per view, nested levels without gaps, sizes from CSS or the type scale; descriptive heading and label text.
- **Impact:** screen-reader users navigate by headings; a broken outline hides the page structure.
- **Source:** WCAG 2.2 SC 1.3.1, SC 2.4.6 Headings and Labels.

### AXE-09 [HIGH] UI parts below 3:1 or lost in forced colours
- **Detect:** input borders, icons, focus rings, checkbox and toggle states and chart marks below 3:1 against adjacent colours; state shown only through `background-image` or `box-shadow`, which forced-colours mode removes; `forced-color-adjust: none` without a replacement; no `prefers-contrast` handling where the theme has low-contrast decoration.
- **Mech:** T `git grep -nIE 'forced-color-adjust:[[:space:]]*none|-ms-high-contrast' -- '*.html' '*.css' '*.scss' '*.less'`
- **Fix:** raise component colours to 3:1; draw boundaries and states with borders or outlines that survive forced colours; test with Windows contrast themes or the `forced-colors` emulation.
- **Impact:** low-vision users cannot find fields or tell whether a toggle is on.
- **Source:** WCAG 2.2 SC 1.4.11 Non-text Contrast; MDN, forced-colors media feature.

### AXE-10 [MEDIUM] Touch or click target too small
- **Detect:** interactive targets under 24 × 24 CSS px without enough spacing (inline text links are exempt); on touch platforms, targets under the platform minimum (44 × 44 pt iOS, 48 × 48 dp Android).
- **Mech:** M (rendered sizes; an engine run's `target-size` result)
- **Fix:** enlarge the hit area with padding or a minimum size token, not the icon.
- **Impact:** users with tremor or on a moving bus hit the wrong control, often a destructive one.
- **Source:** WCAG 2.2 SC 2.5.8 Target Size (Minimum); Apple HIG and Material, touch targets.

### AXE-11 [MEDIUM] Status change not announced
- **Detect:** errors, results counts, saves and toasts that appear visually but are not in a live region or announced (Flutter `SemanticsService.announce`/`liveRegion`, iOS `AccessibilityNotification.Announcement`, Android `liveRegion`); live regions inserted at the moment of the message (not announced); `assertive` or `role="alert"` on routine updates; many scattered live regions.
- **Mech:** T `git grep -nIE 'aria-live="assertive"|role="alert"' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'`
- **Fix:** one polite and one assertive region present from load; route messages through them; assertive only for errors that block the task.
- **Impact:** screen-reader users never learn the form failed or the save succeeded, or are interrupted by every minor update.
- **Source:** WCAG 2.2 SC 4.1.3 Status Messages; MDN, ARIA live regions.

### AXE-12 [MEDIUM] Motion that cannot be reduced or stopped
- **Detect:** non-essential animation, parallax and auto-advancing content with no `prefers-reduced-motion` (or platform reduce-motion) branch; carousels, tickers and auto-updating content over 5 s with no pause or stop control.
- **Mech:** T `git grep -qIE '@keyframes|animation:' -- '*.html' '*.css' '*.scss' '*.less' && ! git grep -qI 'prefers-reduced-motion' -- ':!*.md' && echo 'animations without any prefers-reduced-motion query'`
- **Fix:** gate decorative motion on the reduce-motion setting (`MediaQuery.disableAnimations`, `UIAccessibility.isReduceMotionEnabled`, Android animator scale); a visible pause control for moving content.
- **Impact:** motion triggers nausea and dizziness for vestibular disorders, and moving content defeats attention-impaired users.
- **Source:** WCAG 2.2 SC 2.2.2 Pause, Stop, Hide (A); SC 2.3.3 Animation from Interactions (AAA).

### AXE-13 [HIGH] Page scaffold missing: language, title, landmarks, skip link
- **Detect:** `<html>` without `lang`; foreign-language passages without their own `lang`; routes that never update `document.title`; no `<main>` or landmark structure; no skip link before repeated navigation.
- **Mech:** S `git grep -nIE '<html(>|[[:space:]][^>]*>)' -- '*.html' | grep -vE '<html[^>]*[[:space:]]lang='`
- **Fix:** set `lang` from the active locale; update the title on every route; wrap regions in `header`, `nav`, `main`, `footer`; add a skip link to `main`.
- **Impact:** screen readers mispronounce the whole page, and keyboard users re-tab through navigation on every page.
- **Source:** WCAG 2.2 SC 2.4.1 Bypass Blocks, 2.4.2 Page Titled, 3.1.1 Language of Page, 3.1.2 Language of Parts.

### AXE-14 [MEDIUM] Input purpose and keyboard type not declared
- **Detect:** name, email, phone, address, one-time-code and payment fields without the matching `autocomplete` token, or with `autocomplete="off"` on identity fields; numeric, email, phone and URL fields as plain text with no `type`/`inputmode`; native fields without `keyboardType`/`textContentType`/`KeyboardOptions`.
- **Mech:** T `git grep -nIE 'autocomplete="off"' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'` · `git grep -nIE 'TextField\(|TextFormField\(' -- '*.dart'`
- **Fix:** the HTML autocomplete token for each personal field; semantic `type` or `inputmode`; the platform keyboard and content type on native.
- **Impact:** autofill and password managers stop working, and every user types on the wrong keyboard.
- **Source:** WCAG 2.2 SC 1.3.5 Identify Input Purpose; WHATWG HTML, autofill.

### AXE-15 [HIGH] Text cannot be enlarged
- **Detect:** zoom blocked (`user-scalable=no`, `maximum-scale` below 5); OS font scaling disabled or clamped (`TextScaler.noScaling`, `textScaleFactor: 1`, `allowFontScaling={false}`, fixed SwiftUI font sizes, `dp` text in Compose); fixed heights on text containers; text clipped at 200 % zoom or under the text-spacing override (line height 1.5, paragraph 2 em, letter 0.12 em, word 0.16 em).
- **Mech:** S `git grep -nIE 'user-scalable[[:space:]]*=[[:space:]]*(no|0)|maximum-scale[[:space:]]*=[[:space:]]*[0-4](\.[0-9]+)?([^0-9.]|$)|TextScaler\.noScaling|textScaleFactor:[[:space:]]*1(\.0)?([^0-9]|$)|allowFontScaling=\{?false' -- ':!*.md'`
- **Fix:** allow zoom; respect the OS text size (rem/em, `sp`, Dynamic Type styles); `min-height` instead of `height` on text containers; test at 200 % and the largest OS size.
- **Impact:** low-vision users lose content entirely, and default-setting QA never sees it.
- **Source:** WCAG 2.2 SC 1.4.4 Resize Text, SC 1.4.12 Text Spacing.

### AXE-16 [MEDIUM] Focused element hidden under sticky chrome
- **Detect:** `position: sticky`/`fixed` headers, footers or toolbars with no matching `scroll-padding` on the scroll container or `scroll-margin` on targets; anchors and tabbed-to fields landing under the bar.
- **Mech:** T `git grep -nIE 'position:[[:space:]]*(sticky|fixed)' -- '*.html' '*.css' '*.scss' '*.less' '*.vue' '*.svelte'`
- **Fix:** `scroll-padding-top`/`-bottom` equal to the sticky chrome size, from the same token.
- **Impact:** keyboard focus disappears behind the header, as if the focus ring were missing.
- **Source:** WCAG 2.2 SC 2.4.11 Focus Not Obscured (Minimum).

### AXE-17 [MEDIUM] Drag or gesture with no single-pointer alternative
- **Detect:** reordering, moving or resizing only by drag; sliders without arrow keys or a numeric field; pinch, multi-finger or path gestures and swipe-only actions with no button or menu equivalent.
- **Mech:** T `git grep -nIE 'draggable|onDrag|dragstart|Draggable\(|LongPressDraggable|@dnd-kit|react-dnd|sortablejs|onSwipe|Dismissible\(' -- ':!*.md'`
- **Fix:** add a click or keyboard path (move up/down, "move to…", a value field) beside every drag and gesture.
- **Impact:** motor-impaired and switch users cannot drag at all; drag-only means locked out.
- **Source:** WCAG 2.2 SC 2.5.7 Dragging Movements, SC 2.5.1 Pointer Gestures.

### AXE-18 [MEDIUM] Forms that re-ask, block paste or commit without review
- **Detect:** multi-step flows asking again for data given earlier in the session; paste blocked on password or code fields; `autocomplete="off"` instead of `current-password`/`new-password`/`one-time-code`; a puzzle or memory test as the only login path; submissions with financial, legal or data-deleting effect that cannot be reviewed, corrected or reversed.
- **Mech:** T `git grep -nIE 'onpaste|onPaste|on:paste|@paste|\(paste\)' -- ':!*.md'`
- **Fix:** prefill or offer reuse; allow paste and password managers; offer a passkey, magic link or OAuth beside any CAPTCHA; a review step, confirmation or undo for consequential submissions.
- **Impact:** paste blocking punishes users with strong passwords, and every re-typed field multiplies errors.
- **Source:** WCAG 2.2 SC 3.3.7 Redundant Entry, SC 3.3.8 Accessible Authentication (Minimum), SC 3.3.4 Error Prevention (Legal, Financial, Data).

### AXE-19 [MEDIUM] Focus or input changes context unexpectedly
- **Detect:** a `<select>` or field `change` handler that navigates or submits; focus opening a dialog or moving elsewhere; auto-submit on the last character without notice; hover or focus popups that cannot be dismissed with Escape, vanish when the pointer moves onto them, or close on a timer.
- **Mech:** T `git grep -nIE '<select[^>]*(onchange|onChange|@change|on:change)=' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'`
- **Fix:** change context only on explicit activation; popups dismissable, hoverable and persistent.
- **Impact:** screen-reader and magnifier users lose their place or cannot read the popup.
- **Source:** Least astonishment; WCAG 2.2 SC 3.2.1 On Focus, 3.2.2 On Input, 1.4.13 Content on Hover or Focus.

### AXE-20 [MEDIUM] Media without captions or transcript, or autoplaying sound
- **Detect:** `<video>` with speech and no `<track kind="captions">`; audio without a transcript; `autoplay` with sound and no immediate pause or mute; visual-only information in video without a description.
- **Mech:** T `git grep -nIE '<video[[:space:]]|<audio[[:space:]]|autoplay' -- '*.html' '*.jsx' '*.tsx' '*.vue' '*.svelte'`
- **Fix:** captions, transcripts and audio description or a text alternative; no autoplay with sound.
- **Impact:** deaf users miss the content, and autoplaying audio drowns out the screen reader.
- **Source:** WCAG 2.2 SC 1.2.1–1.2.5, SC 1.4.2 Audio Control.

### AXE-24 [HIGH] Colour is the only signal
- **Detect:** errors, status, required fields, chart series or calendar categories told apart only by colour.
- **Mech:** M
- **Fix:** add text, an icon, a pattern or a shape alongside colour.
- **Impact:** users with colour-vision deficiency see no difference at all.
- **Source:** WCAG 2.2 SC 1.4.1 Use of Color.

### AXE-25 [MEDIUM] Orientation locked without need
- **Detect:** portrait or landscape forced in the manifest, `Info.plist`, `SystemChrome.setPreferredOrientations` or a web manifest for content that does not need it; layouts broken in the other orientation.
- **Mech:** T `git grep -nIE 'screenOrientation|setPreferredOrientations|UISupportedInterfaceOrientations|"orientation"[[:space:]]*:' -- ':!*.md'`
- **Fix:** support both orientations unless one is essential (a piano, a cheque scanner) and adapt the layout.
- **Impact:** users with a mounted device (wheelchair, car, stand) cannot use the app.
- **Source:** WCAG 2.2 SC 1.3.4 Orientation.

### AXE-26 [HIGH] Focus lost on route change or dialog close
- **Detect:** client-side route changes that leave focus on the clicked link or `body`; dialogs that do not move focus inside on open, do not contain it while modal, or do not return it to the trigger on close; deleted list items whose focus falls to the page start.
- **Mech:** M (tab through the route changes and dialogs; `inert`, `<dialog>.showModal()` and the router's focus hook are the evidence)
- **Fix:** move focus to the new view's heading or `main` after navigation; use `<dialog>` with `showModal()` or the APG dialog pattern; restore focus to the trigger, or the next item after a delete.
- **Impact:** keyboard and screen-reader users are stranded at the top of the page or in hidden content after every navigation.
- **Source:** WCAG 2.2 SC 2.4.3 Focus Order; W3C APG, Dialog (Modal) pattern.

### AXE-27 [MEDIUM] Navigation and help inconsistent across views
- **Detect:** repeated navigation, search or help links in a different order or place from view to view; the same function labelled or iconed differently (SIM-09 finds the duplicate definitions); a site with a single way to reach a page (no search, sitemap or menu path).
- **Mech:** M
- **Fix:** one shared layout for repeated navigation and help; at least two ways to reach each page in a multi-page site.
- **Impact:** users with cognitive or visual impairments relearn every page and cannot find help when stuck.
- **Source:** Least astonishment; WCAG 2.2 SC 3.2.3 Consistent Navigation, 3.2.4 Consistent Identification, 3.2.6 Consistent Help, 2.4.5 Multiple Ways.

### AXE-28 [HIGH] Time limit without warning or extension
- **Detect:** session or form timeouts that log out or discard input with no warning and no way to extend; timed steps (checkout holds, quizzes) without an adjust option where time is not essential.
- **Mech:** T `git grep -nIiE '(session|idle|inactivity)[_.-]?(timeout|expir)' -- ':!*.md' ':!*test*'`
- **Fix:** warn at least 20 seconds before expiry with a one-action extend; save the input so it survives re-authentication.
- **Impact:** slower readers and assistive-tech users lose their work mid-form.
- **Source:** WCAG 2.2 SC 2.2.1 Timing Adjustable.

### AXE-29 [HIGH] Desktop UI invisible to the platform accessibility API
applies_when: ui∋desktop
- **Detect:** custom-drawn or canvas controls (immediate-mode GUI, game-engine UI, a canvas inside Electron or Tauri) with no exposure to UI Automation, NSAccessibility or AT-SPI; menus and shortcuts that ignore the platform conventions (no menu bar entries, `Ctrl` where macOS expects `Cmd`); bitmaps blurry or layouts broken at 150–200 % display scaling.
- **Mech:** M (inspect with Accessibility Insights, Accessibility Inspector or Accerciser)
- **Fix:** native or accessibility-aware toolkit widgets, or an accessibility tree for custom drawing (AccessKit or the platform API); platform menu and shortcut conventions; vector or multi-resolution assets.
- **Impact:** screen-reader users see an empty window, and keyboard users cannot find commands where their platform puts them.
- **Source:** EN 301 549 clause 11 (software); Microsoft UI Automation, Apple NSAccessibility, GNOME AT-SPI documentation.
