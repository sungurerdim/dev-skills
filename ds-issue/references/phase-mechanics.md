# Reference: Phase 2 (Dedup/Reconcile), Phase 4 (Compose+Create), Phase 5 (Status Audit) Mechanics

Consumer: ds-issue Phase 2, Phase 4, Phase 5. SKILL.md keeps each phase's Gate inline; this file carries the step-by-step mechanics.

## Phase 2: Dedup / Reconcile [intake: full · --sweep: standalone]

1. Search existing issues over **all states**: `gh issue list --state all --limit 1000` + `gh search issues "<keywords>" --repo <slug> --limit 1000` (omit `--state` — spans both); plus the adapter's history/abandoned-decision docs (read as files). `--limit` is mandatory — the default returns 30 and drops the rest without an error, so the duplicate you are looking for is exactly what gets cut; measure the returned count ([github-features.md](github-features.md)) before treating the search as exhaustive.
2. Classify the candidate vs each near-match: duplicate / overlap / redundant / obsolete / net-new. **The commands run and their observed output are captured verbatim** — on intake they go into the new body's Dedup evidence block, on `--sweep` into the report. Writing a verdict without the output that produced it is fabricated evidence and fails the Phase-4 self-check.
3. Conflicts. Default: resolved by best judgment — true duplicate → merge/supersede into the matched issue; ambiguous overlap → new anyway with a cross-reference note; every disposition recorded in the summary (reopenable via `gh issue reopen`, so this is not on the publish/irreversible exception list). `--ask`: present, ask **merge into #N / supersede #N / new anyway / drop** (each close confirmed per item).
4. `--sweep` ends here. Default: every recommended disposition applies automatically — no per-item confirmation — recorded in the summary; the set acted on is exactly the set found. `--ask`: present clusters **transparently** — one compact line per issue (`#N · state · title`) grouped by kind with counts (`duplicate (3) · obsolete (5) · overlap (2)`); offer **per-category bulk** (`Close all obsolete` / `Merge all duplicates into the canonical`) **and** `Apply all recommendations`, plus per-item choice; every close confirmed per item. The set acted on is exactly the set displayed.

## Phase 4: Compose + Create [intake] [GATE]

1. Criteria check — flag conflicts with red-lines/rules; never propose out-of-criteria work. An owner call blocks progress → the body gets an **Open decision** block (question + options with consequences + recommendation with its reason); the answer, when it comes, is written into that same block as `Resolved <date>: …`, never into a comment.
2. **Measure the gate baselines** — run each gate the issue will name, record command + expected + observed-today + date. Unrunnable (needs a credential/hardware) → `baseline unmeasured — <reason>`. A gate with no baseline gives the executor no way to tell an inherited red from one it caused.
3. **Size split.** Within the bounded threshold (≈`BOUNDED_UNIT_FILES` files / one reviewable unit) → one standard issue. Over it → **epic + sub-issues**: the epic body carries the whole's current state, the whole's target, the sub-issues in **binding order** with the reason each order binds, and only whole-level gates; each sub-issue carries its own Current/Target/Delta/Gates/Done and is workable without opening the epic. **Nothing is copied between them** — the epic never restates a sub-issue's Done, the sub-issue never restates the epic's rationale beyond its one context line. Wire the hierarchy natively (`gh issue create --parent`, `gh issue edit --add-blocked-by`) so `--status` reads structure, not prose. Design/architecture still open (the "how" needs decisions, not just work) → `/ds-pipeline` present → route to it for the spec chain first, then file sub-issues from its tasks; absent → file the issue as-is with an `## Open decision` block naming the open design question, gap-note "spec pass not run — requires /ds-pipeline".
4. Fill the body template (conditional blocks; terse for small issues) — [issue-template.md](issue-template.md). Labels from the live set (`gh label list`): exactly 1 type + 1 priority + optional status; issue types only where `gh api /orgs/<org>/issue-types` returns 200 (user-owned repos have none — verified).
5. Self-check ([issue-template.md](issue-template.md) § Self-check gate). Default: a passing self-check is sufficient to create (`gh issue create --body-file -` with a heredoc) or edit a raw issue; the URL is reported in the summary. `--ask`: show the draft, confirm, then create or edit. **Refining an existing issue →** read it with its comments first (canonical read); fold requirement-bearing comments into the body as part of the same draft — under `--ask`, one confirmation covers body + folded comments. **Scope collapsed rather than shifted** (the premise no longer holds, the remaining work is a different issue) → do not stretch the body: write a `## Closure` block into it, open the successor carrying the context restated (not linked-to) plus a `Handoffs — Received from #N` line, link both ways, and close the original `--reason "not planned"`. Return the URL.

## Phase 5: Status Audit [--status] [read-only]

1. For each open + recently-closed issue, read it **with its comments** (the canonical read — [github-features.md](github-features.md)) plus its cited anchors, and run the commands in its **Gates** table and Done list. Judge done-ness **from code**, never from the closed flag or a "done" comment. A requirement-bearing comment is part of the issue's contract — audit it exactly like a body Done item, and record it as a **body defect** to be promoted at the next `--do`.
2. Bucket each (Scopes) with its evidence, comparing each gate against its recorded baseline. A **closed** issue with no `## Closure` block, or one carrying a comment-borne criterion with no code-proven evidence (and no promotion/rejection disposition) → `claimed-done-but-unproven`. Mutate nothing.
3. **Body-health flags** (reported, not fixed — `--status` is read-only): decision or criterion living in a comment · gate named without a command or without a baseline · Done item using a banned phrasing · Current and Target state collapsed into one claim · a `Handoffs — Deferred to #K` line with no counterpart in `#K`.
